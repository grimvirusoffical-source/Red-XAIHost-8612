# Host web vendor cleanup

This change starts at the reviewed production-source backport `152139a621d5aea4579529bb5703d54b8c8ee0ff`. It removes the optional managed-auth broker adapter, browser SDK/bearer injection, badge, development feedback and collector injection from the Host web source. Local Better Auth, direct Google configuration and the canonical website account/session adapter remain. Browser clients use their existing server-validated cookies with credentials included; browser identity fields do not create authority.

The five removed dependency declarations are root `@runablehq/runkit` and web `@runablehq/managed-auth`, `@runablehq/website-runtime`, `jsdom` and `@types/jsdom`. The normalized Bun 1.3.14 lock is `b93c52fbe19afcd8ca7e32445e049223009ecc2ac60ddc8b2d0a97ebef0a4f8e`. Every remaining package tuple already existed identically in the parent lock; this is pruning and locator relocation, with no package upgrade or linker override. Desktop/mobile dependency declarations and source are retained, including the desktop SDK. This is not complete repository-wide vendor removal or desktop/mobile release acceptance.

Existing desktop builds still consume their own `APPLICATION_ID` for OS deep links. Retain that existing desktop build/runtime setting; removing it from the web environment example is not an instruction to clear it. This change does not redesign or validate desktop packaging.

The previous root `lint` and `lint:fix` commands invoked vendor tooling. They now invoke workspace typechecking and the existing formatter respectively. These commands do not preserve every old vendor lint rule. The web typecheck explicitly checks both application and Node/Vite projects instead of the empty root project. The application project explicitly loads already-declared Node types; the Node project declares the standard DOM Request/URL interfaces formerly supplied indirectly by the removed JSDOM plugin. No strictness flag is relaxed. An unused private `loginHint` declaration is removed; its body was never called. The strict application baseline already failed before this cleanup, so its missing ambient types and unused helper are not described as a JSDOM regression.

Validation uses a fresh frozen install, synthetic local databases, existing account/tenant/project-removal and mounted-auth tests, routing/migration checks, both real TypeScript projects and a mounted production web build. `scripts/check-host-web-vendor-surface.mjs` scans the built files for the removed collector/SDK/badge markers and legacy files, verifies the mounted application assets and retains the first-party Quick Login script reference. These checks establish source/build behavior; they do not establish production normal-account access or installed-client acceptance.

## Deployment boundary

Do not publish this branch's older-baseline frontend over the current C443 Hub/Host design. Current production static assets, account authority, native RedX engine/BoxQL/data formats, CLI, Quick Login and Secrets clients are outside this change. A backend upgrade still needs exact runtime/configuration and current-data backup/restore checks, tenant acceptance and code/configuration rollback preserving current data. Check deployments that deliberately enabled the removed broker before upgrading them; this source intentionally removes that optional provider rather than promising its authentication protocol remains supported.

The separate bounded CI does not relax the earlier production-backport workflow's protected account/dependency guard. No installer, provider provisioning, worker enrollment, publication, service restart or production migration is performed by this source change.
